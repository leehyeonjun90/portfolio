# 산업 제어 시스템 - 절전 기능 개발

**현장실습 - Single Master 패턴으로 제어 충돌 해결**

---

## 📌 프로젝트 개요

### 한 문장 요약
**기존 PLC 시스템에 절전 기능을 추가하면서 발생한 제어 충돌을 Single Master 패턴으로 해결**

---

## 🎯 상황: 절전 기능 추가 시 제어 충돌 발생

### 배경
기존 산업용 커피 디스펜서 시스템:
- PLC가 릴레이를 토글 방식으로 제어 중 (안정적)
- **내가 추가한 기능**: 절전 모드 (MCU가 타이머 후 자동 OFF)

### 발생한 문제
```
PLC: "내가 ON 했으니 ON 상태겠지?"
MCU: "시간이 되었으니 OFF 했어"
PLC: "뭐? 내가 ON 했는데 OFF라니?"
     → 다시 ON
MCU: "또 ON 되었네. 시간이 되면 OFF"
     → 무한 반복 ❌
```

---

## 💡 원인 분석

**Single Master 구조 붕괴**
- PLC와 MCU가 동시에 릴레이 제어
- 상태 동기화 없음
- 제어 기준 불명확

---

## ✨ 내가 해결한 것

```
Before: PLC와 MCU가 동시에 제어 (충돌)
          ↓
After:  PLC = Single Master (유일한 제어권)
        MCU = Slave (PLC 상태만 따름)
             ↓
        상태 동기화 → 안정성 확보 ✓
```

---

## 🛠️ Single Master 패턴 구현

### Before (문제)
```cpp
if (timeout > 900000) {
    relayControl = OFF;  // MCU가 강제로 OFF
}
```

### After (해결)
```cpp
if (plcStatus == SLEEP_MODE) {
    // PLC의 상태를 따름
    // MCU는 타이머만 관리
    if (timeout > 900000) {
        // 로그만 남김
    }
}
```

---

## 📊 상태 동기화

- **PLC**: 상태 신호 송신
- **MCU**: PLC 상태 수신 후 종속적으로 동작
- **명확한 제어 기준 설정**

---

## 🎓 배운 점

### 1️⃣ Single Master 패턴의 중요성
- 한 시스템만 제어권을 가져야 함
- 다른 시스템은 상태만 따름

### 2️⃣ 기능 추가 시 기존 구조 존중
- 새 기능이 기존 시스템을 깨면 안 됨
- 호환성 확보 필수

### 3️⃣ 산업 기계의 "안정성 > 기능" 원칙
- 24시간 가동하는 시스템은 신뢰성이 최우선
- 고장나면 생산이 멈춤 = 막대한 손실
